# Pre-Design Checklist

Complete before choosing visual styling.

- [ ] Primary user job is written as a concrete verb/object task.
- [ ] Product type and core objects are identified.
- [ ] Industry is treated as a workflow prior, not a theme preset.
- [ ] User expertise and usage frequency are known/inferred.
- [ ] Consequence of error and risk level are classified.
- [ ] Information density is based on real decision volume, not aesthetic preference.
- [ ] Primary platform and input modes are identified.
- [ ] Accessibility/legal constraints are known.
- [ ] Existing design system/tokens/components are inventoried.
- [ ] Brand traits are normalized; max two drivers selected.
- [ ] Conflicting traits have separate driver/modifier/guardrail roles.
- [ ] Critical/non-hideable information and actions are marked.
- [ ] Major responsive components have a minimum usable-width hypothesis.
- [ ] Table/chart/dashboard tasks are classified before choosing their visual form.
- [ ] Semantic color roles are listed before hex values.
- [ ] Semantic typography roles are listed before exact sizes.
- [ ] Marketing, product, and critical-workflow expression levels are intentionally separated when relevant.
- [ ] Product-specific nouns/data/states are available so design does not depend on placeholder rectangles.

If several items are unknown, choose restrained/conventional interaction patterns and mark assumptions rather than inventing a strong aesthetic premise.
